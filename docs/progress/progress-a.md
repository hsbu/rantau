## Agreed foundation decisions and integration boundaries

- The requester approved the S-01/S-02/A-01 proposal on 2026-10-16 and confirmed the product name Rantau. This file consolidates the former foundation notes and implementation proposal; executable field definitions remain in `backend/contracts/`, with product requirements in the MVP/roadmap.
- Money uses strict nonnegative JavaScript-safe integers: IDR scale 0 (whole rupiah), CNY scale 2 (fen). Payment amounts are positive. Quote rates are exact decimal strings in destination major units per source major unit, rounded half up to destination minor units; totals equal principal plus fee. Times are timezone-aware. `terms_hash` is an opaque trusted-service digest, never generated authority from the agent.
- Fixture aliases remain `stu_001`, `par_001`, `acct_idr_01`, `uni_cn_01`, `obl_2026_demo_01`, `benef_uni_cn_01`, `quote_001`. The fictional November clock, two quotes and errors live in `tests/fixtures/`. Both quotes deliver CNY 20,000 for IDR 46,025,000 / 46,050,000 and expire after 15 simulated minutes. Fake execution cannot approve or debit.
- Actor identity comes from a verified server session, never a message/header claim. `verified_actor` and `agent_services` stay closed until real B/C adapters are connected; no mock gate is loaded in the integrated application. `RunRepository` is an integration seam, not durable production storage. The DB probe does not create migrations or financial tables.
- Payment delivery and verified university posting are distinct. `UniversityPort.reconcile` submits/rechecks evidence; it cannot approve cases or post credit. The A-01 graph receives only read/triage capabilities and no executor, approval writer, hold-clearing or ledger-posting tool. Tests assert forged authority cannot change actor context and provider uncertainty cannot cause a retry.
- The initial 2026-10-16 OpenAI adapter (superseded by A-OR-01 on 2026-10-17) receives bounded user text with common sensitive identifiers redacted, not server actor/session data, balances or tool output. Classification returns only an allowed intent or clarification; graph paths, tools and deterministic replies remain fixed. The adapter uses `OPENAI_MODEL`, bounded retries/output and `store=False`, with safe refusal/invalid/incomplete/timeout/error handling. Live model access, accuracy and latency have not been measured.
- A-01 originally ran single-turn. A-03 now uses the existing `conversation_id` to retain scoped tuition draft selections, while omitted IDs keep stateless behavior. Tracking still recognizes explicit synthetic `transfer_...` references; general transcript memory and reference resolution for other workflows are not implemented. Verified payment-to-obligation linkage, approval continuation and recovery execution remain later tickets. A-06 implements the UI; its trusted browser/backend integration remains open in the gaps section.
- Generated OpenAPI/TS, environments, caches and temporary PR bodies stay ignored. Lockfiles are committed. ESLint 10/TypeScript ESLint replaces the Next-specific preset after its transitive glob dependency audit finding; Next compilation/types still run separately.

## A-03 conversation and provider decisions

- The requester selected OpenRouter and explicitly approved tuition conversation state on 2026-10-17. `OPENROUTER_API_KEY` and `OPENROUTER_MODEL` replace the old direct-provider variables. The compatible SDK targets only `https://openrouter.ai/api/v1` by default. [Structured-output routing](https://openrouter.ai/docs/guides/features/structured-outputs) requires supported parameters; the request also uses the documented [provider data-collection preference](https://openrouter.ai/docs/guides/routing/provider-selection#requiring-providers-to-comply-with-data-policies). Routing preferences are not independent privacy/compliance verification. Local key/model were unset when checked; live model behavior remains unverified.
- Typed interpretation contains only option ordinals, requested CNY amount, funding-owner preference, route preference and an explicit restart. It cannot carry identity, account IDs, payee changes or approvals. Current user text is redacted; only the prior intent, pending field and option counts accompany it to the model. No raw transcript, server IDs, balances, quote bodies, credentials or authorization objects enter conversation model context.
- State keys include verified tenant/student/session plus the client conversation ID. Turns on one key serialize; inactive drafts expire after 30 minutes and total storage is capped at 128 conversations. A new ID, explicit restart, process restart or expiry starts fresh. This first adapter supports one worker/process only; `ConversationStore` is the seam for coordinated durable storage later.
- Remembered selections are revalidated against fresh scoped reads. Removed funding and expired/replaced quotes require a new choice. The backend uses a server-configured university-to-registry binding and checks beneficiary ID, ownership, verification and fingerprint. The typed `IntentProposal` is a preview only: no intent persistence, approval request/decision, debit, posting or hold clearing occurs. A-04 will attach protected continuation to actual server intent/approval state.
- The explicit `--openrouter` CLI harness uses live interpretation with synthetic adapters and the fixed November scenario clock; it is separate from application wiring. `/api/v1/agent/messages` continues to fail closed without B/C authentication/domain adapters. The existing HTTP schema is unchanged; browsers may send the existing `conversation_id` field to retain tuition selections once trusted services are connected. A-06 now supplies a connected workspace and an isolated scripted fixture preview; trusted B/C services and structured financial-detail integration remain pending.
